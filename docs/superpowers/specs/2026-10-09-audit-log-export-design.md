# Audit Log Date Range + Excel Export — Design Spec (2026-10-09)

## Goal
Custom from/to date filtering on both audit log pages (super-admin + auditor)
plus an Excel export of the filtered audit rows. Follows Option A: extend the
read path, add a REST binary endpoint, reuse both existing precedents.

## Decisions (from brainstorming)
- Scope: audit log rows with current filters applied, on BOTH
  `/super-admin/audit-log` and `/auditor/audit-log`.
- Date UX: custom From/To date fields; empty means unbounded.
- Permission: NEW `audit:export` granted to SUPER_ADMIN + AUDITOR (NOT reuse
  `reports:export`, which would leak transaction-ledger exports to auditors).
- Export content: grid columns (Time, Actor, Action, Resource, Details),
  uncapped full filtered set (report precedent, up to REPORT_ROW_LIMIT 100k).

## Amendment to auditor spec (2026-10-08)
Auditors were strictly read-only with NO exports. This spec grants auditors
the audit-log Excel export ONLY. Transaction-ledger exports still require
`reports:export`, which auditors do not have. No other write access changes.

## 1. Backend date filters
- `AdminService.list_audit_logs(limit, offset, action, search, from_date=None, to_date=None)`:
  `from_date`/`to_date` are `YYYY-MM-DD` strings; filter
  `AuditLog.created_at >= from 00:00 UTC` and `< (to + 1 day) 00:00 UTC`.
  Empty/None means unbounded on that side. Invalid format raises
  `ValidationError` naming the expected format. Count query uses the identical
  filter list (no count/page drift).
- `auditLogs` / `auditLogsCount` resolvers gain `from_date`/`to_date` args
  (Strawberry camelCase: `fromDate`/`toDate`), same `require_perms(AUDIT_READ)`
  guard, same `try/finally: session.close()`.

## 2. `audit:export` permission
- `Permission.AUDIT_EXPORT = "audit:export"` in `backend/app/core/rbac.py`.
- `ROLE_PERMISSIONS[AUDITOR]` gains `AUDIT_EXPORT` (SUPER_ADMIN via `_ALL`;
  ADMIN explicitly excluded). Mirror in `frontend/src/rbac.ts`.
- Migration `011_add_audit_export.py` (rev 011, revises 010, 010-precedent
  pattern): seeds ONLY the `('AUDITOR', 'audit:export')` row. SUPER_ADMIN is
  synthesized, never stored; ADMIN untouched. Downgrade deletes that row.

## 3. Excel endpoint + generator
- `generate_audit_log_excel(rows)` in `backend/app/domains/admin/reports.py`
  (openpyxl, same header styling as `generate_all_transactions_excel`):
  columns Time, Actor, Action, Resource, Details; title
  "Campe Wallet Audit Log", generated-at line, total-rows line; empty set
  still returns a valid workbook with a note row.
- `GET /admin/reports/audit-log.xlsx` in `backend/app/api/reports.py`,
  gated by `require_perms_token(Permission.AUDIT_EXPORT)`, query params
  `action`/`search`/`from_date`/`to_date`, reuses `list_audit_logs` with a
  high limit (full filtered set up to REPORT_ROW_LIMIT). Returns
  `ccash-audit-log-<timestamp>.xlsx` via the existing `_download` helper.

## 4. Frontend (both pages)
- `SuperAdminAuditLog.tsx` + `AuditorAuditLog.tsx`: From/To date fields
  (MUI `TextField type="date"`, `InputLabelProps={{ shrink: true }}`, no new
  deps) wired into `GET_AUDIT_LOGS` / `GET_AUDIT_LOG_COUNT` variables
  (`fromDate`/`toDate`, null when empty; reset page on change).
- Export button (Download icon) calling existing
  `downloadReport('/api/admin/reports/audit-log.xlsx?' + params, filename)`
  with the current action/search/from/to values. Grid, chips, pagination,
  helper copy unchanged.

## 5. Errors / tests
- Bad date format: `ValidationError` ("expected YYYY-MM-DD") → generic
  GraphQL error client-side; REST endpoint → 400 with detail.
- Tests: date filter narrows items AND count identically; invalid date raises;
  `ROLE_PERMISSIONS[AUDITOR]` exact set extended with `audit:export`;
  endpoint 403 without the perm / 200 with it; generated bytes load via
  openpyxl with the 5 expected headers; frontend `tsc` + build.

## Out of scope
- Preset ranges (Today/Last 7/30 days), time-of-day selection (date granularity only).
- PDF or emailed audit exports; ledger export changes; per-user audit scoping.
- Any other auditor write access (still read-only + this export).
